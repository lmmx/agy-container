# Architectural Comparison: `claude-container` vs. `agy-container`

`agy-container` is a clean-room sibling to [`lmmx/claude-container`](https://github.com/lmmx/claude-container), designed specifically for Google Antigravity CLI (`agy`) rather than forked into a multi-agent wrapper.

Every architectural decision from `claude-container` — plus Antigravity-specific prior art (`shelajev/agy-sbx-kit` and Antigravity's built-in Linux sandbox) — is categorized below as **Retained**, **Adapted**, **Replaced**, or **Discarded**.

---

## 1. Decision Matrix

| Area | `claude-container` | `agy-container` | Status | Rationale |
| --- | --- | --- | --- | --- |
| **Rootless Podman `--internal` network** | `caged` (`internal: true`) + `egress` | Per-run `agy-caged-<run_id>` (`--internal`) + `agy-egress-<run_id>` | **Retained** | Kernel-enforced network namespace isolation requires no `NET_ADMIN`, `NET_RAW`, or host iptables rules, and cannot be modified from inside the workspace. |
| **Container orchestration** | `podman-compose` (`compose.yml`, `compose.locked.yml`, `compose.headless.yml`, `compose.gitgateway.yml`) with fixed project name `claude-container` | Direct `podman` CLI calls (`network create`, `create`, `network connect`, `start`, `run`, `rm`) managed by RAII [`RunTopology`](../src/podman.rs) | **Replaced** | Fixed compose project names break concurrent runs (the first session to exit tears down the other's proxy and cross-contaminates `egress.log`), require Python `podman-compose`, and can swallow `podman logs` on dead sidecars. Direct Podman enables per-run isolation, zero Python deps, and deterministic cleanup. See [ADR-001](adr/001-direct-podman-over-compose.md). |
| **Egress proxy engine** | Alpine 3.20 + pinned `squid=6.9-r0` (`USER squid`), forward `CONNECT` on port `3128` | Alpine 3.20 + pinned `squid=6.9-r0` + `ca-certificates` (`USER squid`), `--read-only` rootfs, `noexec,nosuid` tmpfs, port `3128` + port `3129` | **Retained & Strengthened** | Squid gives auditable, non-MITM hostname filtering. `agy-container` hardens the proxy container with `--read-only` rootfs, adds `ca-certificates` for verified TLS upstream forwarding on port `3129`, and caps proxy resources (`512m` / `256` pids). |
| **SSRF / private-IP blocking in Squid** | Not defined in `squid.conf` or `squid.permissive.conf` | `acl private_dst dst` covering loopback, RFC 1918, link-local (`169.254.0.0/16`), CGNAT (`100.64.0.0/10`), `::1`, `fc00::/7`, `fe80::/10` denied **before** all allows in **both** `squid.conf` and `squid.permissive.conf` | **Adapted** (Strengthened) | Prevents SSRF, cloud-metadata probing (`169.254.169.254`), and host-LAN pivoting even when `-n` / `--probe` is active. Verified by unit tests and `tests/podman_live.sh`. |
| **API credential brokerage** | Not present (Claude auth resides in `~/.claude-container.json`) | Zero-MITM reverse-proxy broker on Squid port `3129` (`--auth api-key` / `--api-key-file`) | **Replaced** (New capability) | Keeps `GEMINI_API_KEY` completely out of the workspace container without generating or trusting a MITM CA. Squid strips client `X-Goog-Api-Key`, restricts paths to `^/v1(beta)?/`, injects the real key, and forwards over verified TLS to `generativelanguage.googleapis.com:443`. See [ADR-003](adr/003-auth-isolation-and-brokerage.md). |
| **OAuth & auth state isolation** | Single host-isolated pair `~/.claude-container.json` + `~/.claude-container/` | 4 auth modes (`oauth`, `api-key`, `gcp`, `adc`); named XDG profiles under `~/.local/share/agy-container/profiles/<profile>/`; `--isolated` ephemeral per-run state copying only the OAuth token | **Adapted** | Antigravity supports consumer OAuth, API key, Enterprise GCP, and ADC, stores SQLite WAL state under `~/.gemini`, and issues OAuth tokens with `cloud-platform` scope (`antigravity-cli#592`). Multi-profile + `--isolated` prevents SQLite WAL lock contention and cross-session hook persistence. |
| **Egress allowlist & `--allow` groups** | Core: `api.anthropic.com` (+ commented auth); 4 groups: `anthropic-auth`, `github`, `npm`, `telemetry`; auto-migrates legacy `squid.conf` | Core: 8 `agy_core` domains (deliberately excluding GCP control-plane APIs); 10 groups (`google-auth`, `gcp-enterprise`, `github`, `npm`, `pypi`, `crates`, `go`, `telemetry`, `updater`, `remote-control`) + validated `--allow-host <DOMAIN>` | **Adapted** | Reflects Antigravity's real endpoint topology, adds language package registries (`pypi`, `crates`, `go`) and ad-hoc FQDN allowlisting with strict injection/raw-IP validation, and requires `allow.conf` + `api-broker.conf` includes in custom `squid.conf`. |
| **CLI parser & dependency surface** | `usage-rs` (v6) derive macro; Rust 1.91+; mandatory positional `DIR` (plus extra positional `rw` dirs) | Hand-written zero-dependency Rust parser (`[dependencies]` empty in `Cargo.toml`); Rust 1.80+; `-w/--workspace` defaults to CWD; `--ro` / `--rw` explicit; native `agy` subcommands (`models`, `mcp`, `plugin`, `acp`, etc.) | **Replaced** | Eliminates the entire external crate tree for a security boundary runner. Replacing mandatory positional dirs with `-w/--workspace` (defaulting to CWD) avoids ambiguity with Antigravity's first-class subcommands (`agy-container models`, `agy-container mcp list`, `agy-container login`). |
| **Workspace image & agent install** | `FROM node:20`, `npm install -g @anthropic-ai/claude-code@latest`, user `node` | `FROM mirror.gcr.io/library/debian:bookworm-slim`, fetches official `agy` release manifest, verifies **SHA-512** digest, installs flat binary `/usr/local/bin/agy` (`root:root 0555`), user `agy` (UID/GID `1000`), disables auto-updater (`AGY_CLI_DISABLE_AUTO_UPDATE=true`) | **Replaced** | `agy` is a native compiled binary with no Node.js runtime requirement. SHA-512 verification against Google's release manifest plus read-only root ownership prevents supply-chain drift and in-container binary trojaning. |
| **Resource limits & rootless portability** | Default memory `4g` (`CLAUDE_CONTAINER_MEM`), fixed `pids_limit: 2048` in `compose.yml`, unconditional `userns_mode: keep-id:uid=1000,gid=1000`, skips memory limit if undelegated | Default memory `8g` (`AGY_CONTAINER_MEM`), `--cpus` (`AGY_CONTAINER_CPUS`), default `--pids-limit 4096` (`AGY_CONTAINER_PIDS`) with automatic `--ulimit nproc` fallback when cgroup v2 `pids` undelegated; detects `/etc/subuid`+`/etc/subgid` and uses `crun` single-UID non-root mapping (`1000:0:1` for `agy`, `31:0:1` for Squid) when absent | **Adapted** | Sized for Antigravity's native multi-worker `/swarm` execution (`8g`/`4096`). Probing `memory`, `pids`, `cpu` cgroup controllers individually plus `/etc/subuid` and `crun` lets `agy-container` run strictly non-root on both hardened workstations and restricted CI/devbox VMs without crashing. |
| **SSH `git-gateway` sidecar** | Alpine + pinned OpenSSH `9.7_p1-r5`, port `2222`, `ForceCommand /usr/local/bin/git-policy`, fail-closed policy marker, per-run throwaway keys, build-time `ssh-keyscan`, `--github[=push]`, `--git-key`, `--git-repo` | Alpine + pinned OpenSSH `9.7_p1-r6`, launched per-run (`agy-gitgw-<run_id>`) directly via Podman with `256m`/`256` limits, pinned `/etc/hosts` entry, and directly baked GitHub ed25519 host key verified unconditionally against `GITHUB_SSH_FINGERPRINT` (no build-time `ssh-keyscan` TOFU) | **Retained & Adapted** | Separates credential *use* from credential *possession* and provides operation-level (`git-upload-pack` vs `git-receive-pack`) and repository-level (`--git-repo`) enforcement without TLS MITM or build-time TOFU. |
| **Signal handling & teardown** | Parent ignores `SIGINT` (restored in child `pre_exec`); `SIGTERM` not caught (leaves orphaned containers) | Parent ignores `SIGINT` (restored in child `pre_exec`) **and** installs cooperative `SIGTERM` handler (`podman stop --time 10` -> capture logs -> RAII `Drop` teardown -> exit `143`) | **Adapted** (Strengthened) | Eliminates orphaned workspace containers, sidecars, and networks when terminals close or CI jobs send `SIGTERM`. |
| **Boundary verification & diagnostics** | `--precondition`, `--probe`, `--self-test`, `verify-egress` script, `egress.log` | `doctor` (checks Podman, subuid, cgroups v2, SELinux, images, profile token, and `--precondition`), `--precondition`, `--probe`, `--self-test` (adds `169.254.169.254` SSRF and direct route checks), `verify-boundary` (adds `CapEff`, `NoNewPrivs`, binary immutability, GCP API denials, SSRF checks), `egress.log` | **Adapted** (Strengthened) | Empirically verifies kernel hardening, SSRF blocking, and `#592` GCP control-plane denials rather than egress alone. |
| **Embedded loopback bypass (`NO_PROXY`)** | Not required (no local proxy bypass list beyond proxy vars) | Sets `NO_PROXY=localhost,127.0.0.1,::1,proxy,git-gateway` (and lowercase `no_proxy`) | **Adapted** (New requirement) | Antigravity CLI runs an embedded local gRPC/HTTP language server on loopback and connects directly to `proxy:3129` (API broker) and `git-gateway:2222`; routing loopback through `proxy:3128` would break `agy` and hit `private_dst`. |
| **Nested Antigravity Linux sandbox (`--sandbox` / `bubblewrap` / `exebox`)** | N/A | Explicitly disabled in default `settings.json`; emits warning if user passes `--sandbox` | **Discarded** | Antigravity's Linux terminal sandbox relies on unprivileged Linux user namespaces (`bubblewrap`/namespaces, sometimes referred to alongside desktop `exebox` isolation), which are blocked inside hardened `--cap-drop=ALL --security-opt=no-new-privileges:true` containers. Weakening the outer container to permit nested user namespaces degrades security. See [ADR-004](adr/004-nested-sandboxing.md). |
| **Docker Sandboxes MITM OAuth proxy (`shelajev/agy-sbx-kit` pattern)** | N/A | Rejected in favor of zero-MITM port-`3129` API key broker + isolated OAuth profiles | **Discarded** | See Section 2 below and [ADR-003](adr/003-auth-isolation-and-brokerage.md). |
| **Legacy `squid.conf` auto-migration & `.bak` rewriting** | Auto-inserts `include .../allow.conf` above `http_access deny all` and writes `squid.conf.bak` | Fails closed with a clear error if a user removes `include .../allow.conf` or `include .../api-broker.conf` from `~/.config/agy-container/squid.conf` | **Discarded** | `agy-container` ships both `include` directives in its initial `squid.conf` from v0.1.0; there are no pre-`--allow` legacy user configs to migrate, and refusing to guess edits to a user's policy file is safer. |

## 2. Evaluation of `shelajev/agy-sbx-kit` (MITM OAuth Credential Proxy)

[`shelajev/agy-sbx-kit`](https://github.com/shelajev/agy-sbx-kit) (Apache-2.0) is a Docker Sandboxes v3 workload kit for running `agy` in YOLO mode (`--dangerously-skip-permissions --mode=accept-edits`) inside a Docker microVM sandbox. It demonstrates several valuable Antigravity-specific patterns that informed `agy-container`'s design:
- Setting `SSH_CONNECTION` so `agy` switches from its local `localhost:36742` browser callback to its copy/paste headless OAuth flow.
- Seeding `~/.gemini/antigravity-cli/settings.json` only when absent (no-clobber) and omitting the obsolete `unsandboxed(*)` permission rule.
- Passing both `--dangerously-skip-permissions` and `--mode accept-edits` together because tool approval and file-edit approval are separate switches in `agy`.

However, `agy-container` **discarded** `agy-sbx-kit`'s TLS-intercepting OAuth credential proxy architecture for three technical reasons:

1. **Runtime dependency lock-in:** `agy-sbx-kit` depends on Docker Sandboxes (`sbx`), a proprietary/Docker-specific microVM host daemon and credential proxy. `agy-container` targets standard rootless Podman on Linux with zero host daemons or privileged helpers.
2. **MITM CA trust surface:** Intercepting Google OAuth token exchanges (`oauth2.googleapis.com`) and replacing `Authorization: Bearer` headers on arbitrary Google gRPC/HTTPS endpoints (`daily-cloudcode-pa.googleapis.com`, `cloudcode-pa.googleapis.com`, etc.) requires generating a host MITM root CA, injecting it into the container's trust store, and terminating TLS for every upstream endpoint. A bug in TLS interception or certificate pinning breaks Google's HTTP/2 + gRPC transport or widens the proxy's attack surface dramatically.
3. **Zero-MITM alternative exists for API keys:** For high-assurance isolation against `antigravity-cli#592`, `agy-container` uses Squid's native `accel` reverse-proxy mode on port `3129` (`GOOGLE_GEMINI_BASE_URL=http://proxy:3129`), injecting `X-Goog-Api-Key` and forwarding over standard system-CA-verified TLS to `generativelanguage.googleapis.com:443` — achieving zero secret exposure in the workspace with **zero MITM**.

| [`sethjensen1/claude-container`](https://github.com/sethjensen1/claude-container) | **MIT** | Upstream ancestor of `lmmx/claude-container` (derived from Anthropic's reference devcontainer). MIT-compatible; no code copied into `agy-container`. |
| [`shelajev/agy-sbx-kit`](https://github.com/shelajev/agy-sbx-kit) | **Apache-2.0** | Reference study for Antigravity CLI headless OAuth (`SSH_CONNECTION`), YOLO flag pairing, and `settings.json` schema. Zero code or Dockerfile lines copied; MITM proxy model deliberately not adopted. |
| **Squid (`6.9-r0`) / OpenSSH (`9.7_p1-r6`) / Debian / Alpine** | GPLv2 / BSD / Debian / Alpine | Installed unmodified from official distribution repositories inside runtime container images; not linked into the `agy-container` Rust binary. |
| **Google Antigravity CLI (`agy`)** | Proprietary (Google) | Downloaded at user image-build time from Google's official release manifest with SHA-512 verification; not redistributed in this repository. |
